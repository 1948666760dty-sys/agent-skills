# duty-NRV / Cut Coach v1.4.0 — Regression Audit

日期：2026-09-22

## 目标

验证 v1.4.0 的五类修复：
1. NRV 默认只指个人 NRV；
2. LOGGED 一次性完整交付；
3. Mobile First 纵向进度条；
4. 去重/修正不重复记账；
5. “今日”等短句能进入完整 REPORT。

## 静态锚点检查

- version = 1.4.0
- 默认个人目标 = 2100 kcal / P120 / C220 / F60 / fiber30
- 默认核心营养 = kcal / protein / carbs / fat / fiber
- 用户界面默认词 = 个人 NRV
- 官方 NRV 默认禁止
- Mobile First 方案三存在
- Response Guard 存在
- 去重/幂等存在
- No-Rush 联动存在
- 餐次防猜存在

## 回归场景

### A. NRV 防呆
1. “今日 NRV” → 个人 NRV，不显示官方 NRV
2. “NRV 呢” → 个人 NRV
3. “官方 NRV 是多少” → 可显示官方 NRV，但必须明确标注官方
4. “中国营养标签 NRV” → 官方概念，不覆盖个人目标
5. “duty-NAV” → 兼容到个人 NRV
6. “个人 NRV” → 个人目标
7. “今天营养成分表和 NRV” → 核心 5 项 + 个人 NRV
8. 用户未提官方 NRV → 禁止擅自出现官方 NRV

### B. LOGGED 一次性交付
9. “吃了这个” + 食物图 → 本餐 + 今日累计 + 个人 NRV + 缺口 + 下一步
10. “喝了这个” + 饮料图 → 同上
11. “刚吃完” → 同上
12. “记录这顿” → 同上
13. “午饭吃了这个” → 同上
14. “又吃了一根香蕉” → 新增一条并重算
15. LOGGED 回答只给本餐 → FAIL
16. LOGGED 回答漏今日累计 → FAIL
17. LOGGED 回答漏个人 NRV → FAIL
18. LOGGED 回答漏下一步 → FAIL
19. LOGGED 默认展开全天每餐宽表 → FAIL（用户未要求时）
20. LOGGED 默认出现官方 NRV → FAIL

### C. REPORT / 短句
21. 已有饮食上下文 + “今日” → 完整 REPORT
22. 已有饮食上下文 + “今天” → 完整 REPORT
23. “今日总共多少” → 完整 REPORT
24. “今日总营养成分表” → 核心 5 项
25. “今天吃了什么” → 总计 + 已记录内容 + 阶段 + 下一步
26. “今天喝了什么” → 同上
27. “今天整体怎么样” → 同上
28. “今日”只返回 kcal → FAIL
29. “今日”只返回 kcal + protein → FAIL
30. 今日记录不完整却说“全天总摄入” → FAIL

### D. 移动端展示
31. 默认使用纵向进度条 → PASS
32. 默认使用 5～8 列横表 → FAIL
33. 108% 时进度条图形封顶 100%，文字保留 108% → PASS
34. 估算百分比使用 ≈ / 约 → PASS
35. 视觉估算误差明显时补合理范围 → PASS
36. 进度条本身被描述成精确测量 → FAIL
37. 用户明确要“详细表格” → 允许横表
38. 用户要求“简短” → 可压缩，但核心总计与个人 NRV不能错误替换

### E. 去重 / 修正
39. 同一餐问“为什么这么高” → 不新增
40. 同一餐问“今日” → 不新增
41. 同一张图再次用于复盘 → 不新增
42. “米饭其实只吃一半” → 覆盖原米饭并重算
43. 剩饭照片 → 修正原条目，不新增第二餐
44. “这瓶只喝一半” → 覆盖为 50%
45. “不是一勺，是两勺” → 覆盖数量
46. “又喝了一瓶” → 明确新增第二条
47. 多次 CORRECTION → 始终基于最新状态，不叠加历史差值
48. 无法判断“补充信息还是又吃一份”且会显著改变累计 → 允许问一个高影响问题

### F. 餐次与范围
49. 16:42 吃主餐但未说晚餐 → 不自动写“晚餐完成”
50. 用户明确“这是晚饭” → 可写晚餐
51. 只有早餐记录 → 写“当前已记录”，不声称全天
52. 三餐均确认记录 → 可标覆盖度高/FULL 或 ESTIMATED
53. 食堂混合菜三餐齐 → 覆盖度高但可信度可为 C/D
54. 高不确定性聚餐 → 不用进度条伪装绝对精确

### G. 默认营养字段
55. 默认显示热量、P、C、F、纤维 → PASS
56. 默认额外强塞钠/糖/胆固醇 → FAIL
57. 用户主动问钠 → 可展开钠
58. 包装标签是当前问题重点 → 可展示标签额外字段
59. 无法可靠估算钾/钙等却给精确值 → FAIL
60. 默认目标仍为 2100/120/220/60/30 → PASS

## 规格级结论

以上 60 个场景定义了 v1.4.0 的唯一预期行为。静态锚点已在写入前校验。

注意：这属于规格级/静态回归，不等于独立模型真实执行 60 次 live evaluation。若未来需要模型级回归，应让独立 Agent 按 60 条逐条生成 observation 并记录 PASS/FAIL。
