# Cut Coach v1.2.0 — Trigger Audit 100

日期：2026-09-21

目标：扩大触发范围，重点消除“本人下一餐决策”和“短句上下文追问”的漏触发，同时保持“不误记账”。

## 判定口径

- **LOGGED**：明确已吃/已喝/正在吃/要求记录。
- **PRE_EAT**：本人当前或下一餐决策；触发但不记账。
- **REPORT**：当天/周/月汇总、剩余、缺口。
- **CORRECTION**：修正既有记录。
- **ANALYZE_ONLY**：一般营养分析；可使用 Skill 规则，但不记账。
- **NO_TRIGGER**：明显不是本人饮食/营养/摄入决策。

## 审计结论

v1.1.0 的主要漏触发点，是“用户没有说计算/记录，只是在问自己下一顿吃什么”以及“已有饮食上下文后的短句追问”。v1.2.0 把这两类明确提升为强触发。

### 防漏触发
必须覆盖：
- “晚上推荐吃什么 / 今晚吃啥 / 晚饭推荐”
- “我现在吃什么 / 下一顿怎么吃”
- “这个现在适合喝吗 / 睡前还能吃吗”
- “训练后吃什么 / 骑完车怎么吃”
- “晚上呢 / 这个呢 / 换一个 / 还有别的吗”（已有饮食上下文）
- “duty-NRV / duty NRV”习惯别名

### 防误记账
扩大触发不等于扩大记账：
- PRE_EAT：不记账
- ANALYZE_ONLY：不记账
- REPORT：不记账
- CORRECTION：只改原记录
- 只有 LOGGED 新增摄入

### 防误触发
明确保持 NO_TRIGGER：
菜谱、食物历史、翻译/发音、广告文案、虚构设定、宠物喂养、纯餐厅营业/订位、企业/股票/供应链、化学、游戏术语、Apple 手机等。

## 规格级结果

**100/100 个场景均有唯一预期路由，覆盖 20 LOGGED + 30 PRE_EAT + 13 REPORT + 10 CORRECTION + 12 ANALYZE_ONLY + 15 NO_TRIGGER。**

这是自然语言 Skill 的语义回归语料，不是传统代码 matcher 单元测试；以后修改触发规则时应复跑同一组场景。
